\section{Abstract}
% =========================================================

FormBot is a Retrieval-augmented generation (RAG) system that answers questions about State Bank of India (SBI) forms with strictly grounded evidence. The work began with a 206-question manual dataset, expanded with \textasciitilde1{,}100 LLM-generated questions to stress-test retrieval and generation. The system evolved from a nearest-neighbour baseline to a hybrid pipeline combining a Neo4j knowledge graph, ChromaDB vector search, early-stage Elasticsearch/BM25 experiments, and cross-encoder reranking, all measured with an LLM-as-judge evaluation harness. The final design delivers grounded answers, live multimodal support (voice and vision), and reproducible evaluation across iterations. Retrieval quality remained the dominant bottleneck; metadata quality, hybrid search, and reranking produced the largest gains.

% =========================================================
\section{Introduction}
% =========================================================

SBI forms are dense, procedural, and varied across products. FormBot was created to help applicants and staff get precise answers grounded in official documents while accommodating scanned forms, tables, and scraped text. Source code: \href{https://github.com/Jishnu-Prasad888/FormBot-Agentic-RAG}{github.com/Jishnu-Prasad888/FormBot-Agentic-RAG}.

\section{Problem Statement}
% =========================================================

\begin{itemize}[leftmargin=1.2cm]
    \item \textbf{User challenges}: Scattered procedural details, inconsistent form structures, hard-to-find eligibility rules and document checklists, and multilingual/scanned inputs.
    \item \textbf{Technical challenges}: Retrieval across mixed modalities (PDF, tables, text), reducing hallucinations, avoiding scheme drift, and keeping answers tightly grounded.
    \item \textbf{Constraints}: Banking answers must cite evidence; when evidence is missing, the assistant must refuse or return partial, caveated responses.
    \item \textbf{Objectives}: Deliver a retrieval-grounded assistant that is precise, refusal-capable, and evaluation-backed, with hybrid search (vector + graph + sparse), reranking, and reproducible metrics.
\end{itemize}

\section{System Architecture and Methodology}
% =========================================================

\subsection{High-Level Architecture}
\begin{itemize}[leftmargin=1.2cm]
    \item Document ingestion into ChromaDB collections (forms, metadata tables, FAQs, compiled web text) with rich metadata.
    \item Dual retrieval: dense vector search plus a Neo4j knowledge graph; earlier stages also used Elasticsearch/BM25.
    \item Cross-encoder reranking and form-aware boosting to assemble the final context window.
    \item Generation via GPT-4o-mini under a strict grounding prompt.
    \item Evaluation harness with LLM-as-judge metrics and diagnostic retrieval signals.
\end{itemize}

\subsection{Data and Corpus}
\begin{itemize}[leftmargin=1.2cm]
    \item 29 core SBI forms (account opening/closure, nomination, SSA, SCSS, PPF, PMMY, savings products).
    \item Structured metadata table (eligibility, beneficiary type, required documents, mode of application, offering details).
    \item Glossary and abbreviations (KYC, NEFT, PMJDY, CIF, CKYC, etc.).
    \item Evaluation: 206 manual Q\&A + \textasciitilde1{,}100 LLM-generated Q\&A; later runs used 756-pair subsets.
    \item Primary corpus of \textasciitilde735 SBI banking JSON/TXT/PDF/Markdown files; Elasticsearch is optional and not required to serve data.
\end{itemize}

\subsection{Methodology}
The project followed a diagnose-and-fix loop: run full evaluations, classify failures (retrieval vs. generation vs. corpus gaps), design targeted fixes, and re-run. Metrics were revised when judge behaviour was noisy. Retrieval changes (metadata, hybrid search, reranking) consistently produced the largest gains.

\subsection{Architecture Modes and Feature Flags}
The system operated in two main modes: (1) a lightweight JSON+NumPy cosine RAG with 8 backend files, later re-augmented with persistent Chroma at \texttt{backend/data/chroma/}, multi-file ingestion, and progress UI (GPT-4o-mini + Ollama supported); and (2) a KAG-first stack with Qdrant as the primary vector store, Neo4j/PostgreSQL graph, feature-flagged components, updated health checks, UUID chunk IDs, and Postgres on port 7000, with Chroma retained as a fallback.

\subsection{Agentic Retrieval Pipeline}
\begin{enumerate}[leftmargin=1.2cm]
    \item Intent detection for section and product hints.
    \item Knowledge graph retrieval for candidate document IDs and related context.
    \item Hybrid search with Qdrant/ChromaDB (dense) plus Elasticsearch/BM25 (sparse) fused via RRF.
    \item Two-pass cross-encoder reranking with neighbour expansion, then final top-$k$ selection.
    \item Iterative Elasticsearch enhancement when context is insufficient.
    \item Answer generation under a strict banking-scoped prompt.
\end{enumerate}

Every evaluation query in the KAG mode first pulls Neo4j candidates (seeded automatically from uploads when metadata is present), then hybrid retrieval; a KagGuide frontend view exposes this flow. Metadata-aware RRF combines dense/sparse scores with filters on \texttt{product\_name}, \texttt{category}, \texttt{file\_name}, \texttt{section}, and \texttt{chunk\_index}, plus query expansion and neighbour expansion for recall.

\section{Evaluation Framework}
% =========================================================

\subsection{LLM-as-a-Judge Metrics}
\begin{itemize}[leftmargin=1.2cm]
    \item Accuracy (LLM) -- semantic match to the expected answer.
    \item Faithfulness -- grounded in retrieved context.
    \item Context Precision -- fraction of retrieved chunks that are relevant.
    \item Context Recall -- whether retrieved context contains all needed facts.
    \item Answer Relevancy -- whether the answer addresses the question.
\end{itemize}

\subsection{Retrieval Metrics}
Recall@10/20/50, Mean Reciprocal Rank, and nDCG@10 to isolate retrieval quality from generation quality.

\section{Module-by-Module Implementation}
% =========================================================

\subsection{Ingestion}
\begin{itemize}[leftmargin=1.2cm]
    \item PDF text extraction and chunking (\textasciitilde1{,}500 characters per chunk); filename links to metadata rows.
    \item ChromaDB collections: forms, metadata tables, FAQs, compiled third-party text.
    \item Upload tooling: \texttt{upload\_documents.py} supports recursive folder ingest, dual progress bars, retry/timeout options, per-run retry toggle, env-configurable base URL, and failure logs.
    \item Metadata schema: common keys such as \texttt{document\_id}, \texttt{filename}, \texttt{chunk\_index}, \texttt{category}, \texttt{product\_name}, \texttt{section}, \texttt{file\_name}, \texttt{content\_hash}, plus PDF/Markdown/Table-specific positions (page, table IDs, parent chunk) to support graph seeding and filtering.
\end{itemize}

\subsection{Vector Retrieval}
\begin{itemize}[leftmargin=1.2cm]
    \item Embeddings: OpenAI \texttt{text-embedding-3-small} for both corpus and queries.
    \item Fan-out across collections; merge top candidates before reranking.
    \item Qdrant HNSW index (unsupported \texttt{ef} removed) is the primary store with UUID chunk IDs; Chroma remains a fallback for compact runs.
\end{itemize}

\subsection{Knowledge Graph}
\begin{itemize}[leftmargin=1.2cm]
    \item Neo4j graph with nodes for Document, Chunk, Topic, Column; edges \texttt{HAS\_CHUNK}, \texttt{BELONGS\_TO}, \texttt{HAS\_COLUMN}.
    \item Dual-pass lookup: expand by source document and by query concepts; merge, filter, and fall back to document facts when needed.
    \item Final scale: 1,917 nodes and 1,897 edges.
    \item In KAG mode, uploads auto-seed Postgres/Neo4j with Form/FormVersion/Field/Dependency/Requirement/Regulation nodes; Neo4j client updated to \texttt{AsyncResult.data()} for reliable health checks.
\end{itemize}

\subsection{Reranking and Context Assembly}
\begin{itemize}[leftmargin=1.2cm]
    \item Cross-encoder: \texttt{cross-encoder/ms-marco-MiniLM-L-6-v2} with form-hint boosting; pluggable rerankers include \texttt{BAAI/bge-reranker-base}, \texttt{jinaai/jina-reranker-v2-base-multilingual}, and Cohere.
    \item Assemble top chunks plus graph facts and glossary hits into the final prompt context after hybrid RRF fusion and metadata filters.
\end{itemize}

\subsection{Query Handling}
\begin{itemize}[leftmargin=1.2cm]
    \item Rule-based form-specific detection for reporting and gating.
    \item Query enrichment with form names when present; glossary fast path for definition queries.
\end{itemize}

\subsection{Generation}
\begin{itemize}[leftmargin=1.2cm]
    \item Model: GPT-4o-mini, temperature 0.1; backend configuration toggles allow switching defaults to GPT-5.1 or Ollama-hosted \texttt{banking-assistant} with matching accuracy scorer.
    \item Prompt: strict grounding, refuse when evidence is absent, include numeric/procedural details, partial-answer guidance, scheme-drift warning.
\end{itemize}

\subsection{Evaluation}
\begin{itemize}[leftmargin=1.2cm]
    \item LLM-judge metrics: context hit, meaning match, generation accuracy; diagnostic signals for source matching and KG contribution.
    \item Debug dumps for missed questions; failure buckets for wrong-doc, wrong-chunk, or generation issues.
    \item Pipeline variants: Elasticsearch as a first-class retriever (synonyms \textrightarrow{} vector \textrightarrow{} BM25 \textrightarrow{} ES \textrightarrow{} RRF \textrightarrow{} rerank \textrightarrow{} neighbour expansion), fp16 reranker fallback to safe mode, batch size 4.
    \item Frontend eval pauses a batch when LLM API errors occur and surfaces the failing question; partial results stay in memory only. A slimmed endpoint returns chat-style \texttt{query/response/status} with optional metrics.
\end{itemize}

\subsection{Frontend and Reliability Enhancements}
\begin{itemize}[leftmargin=1.2cm]
    \item Navigation trimmed to focus on core flows; dashboard health map fixed to retain Qdrant/Neo4j statuses and Neo4j health false negatives resolved via \texttt{AsyncResult.data()}.
    \item Evaluation UI adds image OCR upload/server sample buttons and hook-order fix; batches halt cleanly on API errors.
    \item Live Meet adds camera/screen-share paper detection, PiP, device selection, and throttled OCR with persistent context; streaming coroutine stability improved.
    \item OCR tooling: \texttt{helpfull scripts/check\_OCR.py} now supports responses-to-chat fallback, PDF-to-image fallback, progress and retry/timeout flags, API-mode selection, and raw OCR printouts for debugging.
    \item Backend hardening: CORS-safe error middleware, Chroma collection auto-creation, telemetry disabled to avoid upload 500s, and Ollama API compatibility fixes (\texttt{/api/chat} vs. \texttt{/api/generate}).
\end{itemize}

\section{Roadmap and Implementation Goals}
% =========================================================

\subsection{Goal 1: Canonical Government Schemes Data Platform}
Normalized scheme data in SQLite with list/filter/detail APIs; indexed on scheme name, state, ministry.

\subsection{Goal 2: Intelligent Upload and Strategy Selection}
Auto-detect CSV/XLSX/PDF/Markdown/text/audio and route to TableRAG, hierarchical RAG, vector RAG, or speech pipeline; no manual configuration.

\subsection{Goal 3: ChromaDB Vector Store and Embedding Infrastructure}
Centralized embeddings (Nomic Embed Text V2 MOE via Ollama for offline runs; OpenAI embeddings for online) with incremental/batch indexing, re-indexing, metadata filtering, and multi-collection search.

\subsection{Goal 4: Metadata-First Storage}
Every chunk stores filename, document ID/type, section, language, chunk IDs, upload date, retrieval strategy; sample record used in experiments included eligibility, subsection, page number, parent chunk, and upload date.

\subsection{Goal 5: Document Registry Service}
SQLite registry tracking document ID, filename, type, retrieval strategy, language, upload time, chunk count, embedding model, and collection name to support re-index, versioning, deletion, analytics.

\subsection{Goal 6: TableRAG for CSV and Excel}
Schema index for columns/types/relations plus value index for rows/entities; merges both before generation to preserve table structure.

\subsection{Goal 7: Hierarchical Structure-Aware RAG}
Preserve document hierarchy (section \textrightarrow{} subsection \textrightarrow{} chunk) for PDFs/Markdown; include metadata nodes for retrieval.

\subsection{Goal 8: Agentic Retrieval Architecture}
Specialized agents: SQLite, Vector Retrieval, Document Routing, Web Enrichment, Retrieval Evaluation, Coordinator. Query expansion example: ``PM Kisan Karnataka eligibility'' expands to ``Pradhan Mantri Kisan Samman Nidhi'', ``Farmer Income Support'', ``Eligibility Karnataka''. Vector result example: filename \textit{pm\textunderscore kisan\textunderscore guidelines.pdf}, section \textit{Eligibility}, score 0.94.

\subsection{Goal 9: Hybrid Retrieval Layer}
Combine SQL, vector, TableRAG, metadata search, BM25 keyword, and web retrieval; fuse scores, rerank, and assemble final context.

\subsection{Goal 10: Reranking and Context Optimization}
Retrieve top 50, rerank, keep top 5--10; deduplicate, drop distractors, weight metadata.

\subsection{Implementation Milestones}
1) Normalize schemes DB and expose API; 2) Build document registry and validation; 3) Implement upload detection/routing; 4) Add TableRAG, hierarchical RAG, vector RAG pipelines; 5) Integrate ChromaDB collections with metadata filters; 6) Add agent orchestration, retrieval evaluation, reranking, web enrichment; 7) Ship frontend views for schemes, documents, sources, answers.

% =========================================================
\section{Live Multimodal Extension}
% =========================================================

The final phase extended FormBot to voice and vision: Whisper-1 speech-to-text for voice queries, OpenAI TTS for spoken responses, live camera scanning with pHash throttling to feed GPT-4o/Gemini for field extraction, and stateful session tracking for evolving form values. OCR providers are switchable (Gemini/OpenAI/Ollama), with OpenAI set as default after experimentation. An ASR audio dataset was collected via the Read with Spire app with curated prompts and supervised data collection.

% =========================================================
\section{Conclusion and Future Scope}
% =========================================================

FormBot evolved from a nearest-neighbour baseline to a knowledge-augmented, multi-agent RAG system with live multimodal support. Retrieval quality, not model choice, dominated accuracy: better metadata, hybrid search, and reranking moved scores from the low 40s to \textasciitilde68\%. Next steps include fine-tuning an open-weight judge and retriever, expanding Kannada OCR and QA coverage, stabilising ranking-metric evaluation, and deepening OCR/ASR so scanned and spoken inputs perform comparably to text.
